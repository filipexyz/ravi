Ravi runs AI agents on your own machine. Each agent keeps persistent sessions, answers in the chat channels you connect (Slack natively, WhatsApp, Telegram and Discord through the Omni bridge), and runs automation on its own: scheduled prompts (cron), event triggers and a periodic heartbeat. Every agent has a permission ceiling, and Ravi decides who can reach it and what a message from each person can make it do.

Ravi also connects to the Ravi Console. After `ravi login`, your agents can publish pages on `ravi.page` and build interactive pages backed by Bases, the typed tables of a Console project.

## How the pieces fit

| Piece | What it is |
|---|---|
| `ravi` | The daemon, a PM2 process. It runs agent sessions, delivers replies, and runs cron jobs, triggers and heartbeats. |
| `ravi-channels` | The native channel runner, a separate PM2 process started with `ravi channels start`. It connects Slack. |
| Omni | The bridge for WhatsApp, Telegram and Discord. It runs as two PM2 processes, `omni-api` and `omni-nats`, and stores its data in PostgreSQL. |
| NATS JetStream | The event bus between all processes, at `NATS_URL` (default `nats://127.0.0.1:4222`). The default install gets it from Omni's `omni-nats`. |
| `~/.ravi/ravi.db`, `~/.ravi/chat.db` | SQLite databases. `ravi.db` holds agents, sessions, instances, routes, settings and tags; `chat.db` holds contacts and their identities. |
| Providers | The model runtime behind each agent: `codex` (the built-in default), `claude`, `pi` or `grok`. You choose one per agent. |

You manage all of it with the `ravi` CLI. Agents use the same CLI as their tools, within the permissions you give them.
