# Intelligence proxy runtime contract

The OSS runtime stores only public profile and connection identifiers. `identityd` is the local authority: it resolves Hub membership, returns a short-lived grant and registers a provider-facing signing-forwarder binding. Providers receive only a loopback origin and the public `x-ravi-binding` lookup handle. They never receive a Hub bearer token, upstream API key, signing key, or arbitrary upstream URL.

Each physical provider turn must own a distinct `attemptId`. The first turn may consume the grant reserved during bootstrap when it has at least 30 seconds remaining; every later turn reserves a new grant before its prompt is yielded. A completed, failed, or abandoned attempt is reported to `identityd`. Failover may advance only for a credential failure while `effectState` is `none`.

A physical provider session is compatible only while runtime, profile, selected connection, connection revision, session compatibility key, effective proxy-required policy, provider/model/protocol, forwarder binding identity, and request path remain unchanged. Profile ordering and the effective required policy are represented by `policyCompatibilityKey`. The transient loopback port is deliberately excluded from persisted session fingerprints, but a changed port still requires a fresh physical process because its client configuration is immutable.

Claude proxy sessions load only the protected user settings materialized by Ravi; repository project settings are excluded. The materialized sandbox denies network and Unix-socket access and refuses unsandboxed commands. Dummy auth values used to satisfy provider-client schemas are public protocol markers, not credentials. The local signing forwarder must discard their `Authorization` value and authorize solely from its root-controlled registration plus the exact binding, method, and path.

Proxy mode is fail-closed. A socket is trusted only when it and its ancestry are root-controlled. A same-UID fake socket, a boolean `verified` field, parent PID checks, and lexical command filtering are not proof of principal isolation. Built-in Codex, Claude, and Pi adapters therefore advertise `providerPrincipalIsolation: "none"` until Linux E2E tests prove that provider tools cannot reach the signing listener or broker; active proxy configuration is rejected until then.

`runtime.intelligence.proxy_required=true` activates the global requirement. Per-agent `defaults.intelligence.required=true` activates it for one agent. A profile with `required:false` is a draft and does not alter runtime traffic. Use `ravi agents intelligence` to inspect or edit the ordered public connection preferences.
