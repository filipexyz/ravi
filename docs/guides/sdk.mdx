## Overview

Ravi exposes a typed SDK gateway under `/api/v1/*`. The gateway is generated from
the decorated CLI registry, so SDK clients mirror Ravi commands without
hand-maintained API wrappers.

The current SDK surfaces are:

- TypeScript package: `packages/ravi-os-sdk`
- Swift package: `packages/ravi-os-swift-sdk`
- OpenAPI snapshot: `docs/openapi.json`

The source of truth is `src/cli/registry-snapshot.ts`. OpenAPI, TypeScript, and
Swift are deterministic projections of that registry.

## Start the Gateway

The SDK gateway is mounted on Ravi's webhook HTTP server. The daemon starts that
server only when an HTTP port is configured:

```bash
RAVI_HTTP_PORT=7777
RAVI_HTTP_HOST=127.0.0.1
```

The gateway shares the same listener as webhooks. Requests go to:

```text
http://127.0.0.1:7777/api/v1/...
```

If `RAVI_HTTP_HOST` is not loopback, Ravi refuses to start unless
`RAVI_GATEWAY_NETWORK_AUTHORIZED=1` is set. This keeps the SDK gateway private
by default even when bearer auth is configured.

Set `RAVI_SDK_GATEWAY_DISABLE=1` to disable SDK routes while leaving the HTTP
server available for webhook handlers.

## Context Keys

Non-open SDK routes require a runtime context key (`rctx_*`) in the bearer auth
header. Bootstrap the first admin key on the daemon host:

```bash
ravi daemon init-admin-key
```

For external apps, issue a narrower child context:

```bash
ravi context issue dashboard \
  --ttl 2h \
  --allow view:system:events,view:system:tasks \
  --json
```

The `--allow` format is:

```text
permission:objectType:objectId
```

Examples:

- `view:system:events` for the events stream
- `view:system:tasks` for the tasks stream
- `view:system:audit` for the audit stream
- `access:session:ravi-web` for one session stream

## TypeScript Client

Install:

```bash
bun add @ravi-os/sdk
```

Create a client:

```ts
import { RaviClient, createHttpTransport } from "@ravi-os/sdk";

const client = new RaviClient(
  createHttpTransport({
    baseUrl: "http://127.0.0.1:7777",
    contextKey: process.env.RAVI_CONTEXT_KEY!,
    timeoutMs: 10_000,
  }),
);

const agents = await client.agents.list();
```

Generated method names follow the CLI shape:

```ts
await client.daemon.status();
await client.sessions.read("ravi-web");
await client.instances.routes.add("main", "group:120363428558776322", "ravi-web", {
  channel: "whatsapp",
  session: "ravi-web",
});
await client.sdk.client.check();
```

Kebab-case commands become camelCase methods. For example,
`daemon init-admin-key` becomes `client.daemon.initAdminKey()`.

## Native Channel Backends

Use the provider-neutral channel backend client when an adapter needs to accept
an external message into a local Ravi agent without depending on a provider
payload:

```ts
import {
  RaviClient,
  createChannelBackendClient,
  createHttpTransport,
} from "@ravi-os/sdk";

const ravi = new RaviClient(
  createHttpTransport({
    baseUrl: "http://127.0.0.1:7777",
    contextKey: process.env.RAVI_CONTEXT_KEY!,
  }),
);
const backend = createChannelBackendClient(ravi);

const result = await backend.ingress({
  protocol: "ravi.channel.backend",
  schemaVersion: 1,
  requestId: "request-01",
  idempotencyKey: "provider-message-01",
  localActorId: "actor-01",
  channelInstanceId: "custom-main",
  agentId: "support",
  external: {
    channelKind: "custom",
    connectionId: "connection-01",
    conversationId: "conversation-01",
    senderId: "sender-01",
    messageId: "message-01",
  },
  content: [{ type: "text", text: "Hello" }],
  receivedAt: new Date().toISOString(),
});
```

Ingress requires a concrete `mutate:agent:<agentId>` capability. Ravi persists
one canonical local message and one stable chat/session/turn binding for each
channel-instance idempotency key. A retry with the same semantic request
returns `duplicate` and the original binding; conflicting reuse fails closed.
The local permission decision remains authoritative.

The projected JSON Schema and fixtures live under
`packages/ravi-os-sdk/src/generated` and
`packages/ravi-os-sdk/src/__tests__/fixtures/channel-backend-core`.
Adapters can implement `ChannelOutputSink` to consume validated,
provider-neutral assistant or safe-error envelopes. Runtime lifecycle streams
use the separate `ravi.channel.runtime-events` contract:

```ts
import {
  createChannelRuntimeClient,
} from "@ravi-os/sdk/channel-runtime-events";

const runtime = createChannelRuntimeClient(ravi);
const state = await runtime.readback({
  protocol: "ravi.channel.runtime-events",
  schemaVersion: 1,
  requestId: "readback-01",
  binding: result.binding!,
});

await runtime.interrupt({
  protocol: "ravi.channel.runtime-events",
  schemaVersion: 1,
  requestId: "interrupt-01",
  idempotencyKey: "interrupt-turn-01",
  binding: result.binding!,
  requestedAt: new Date().toISOString(),
});
```

The adapter-side runtime bridge consumes the event contract through
`ChannelRuntimeEventSink`:

```ts
import type { ChannelRuntimeEventSink } from "@ravi-os/sdk/channel-runtime-events";

const sink: ChannelRuntimeEventSink = {
  async emit(event) {
    console.log(event.sequence, event.kind);
  },
};
```

Lifecycle events use a monotonically increasing sequence per local turn and
cover state, phase-tagged assistant messages and deltas, tool summaries,
approvals, and terminal output. Commentary remains a separate lifecycle event;
completed terminal output contains only the final assistant response. Readback
remains available after reconnects, including the canonical assistant message
id and exact durable terminal event after successful completion. The current
and last-event runtime generation ids let a caller distinguish a live
nonterminal turn from state orphaned by a process restart without assuming
that retry is safe. Interrupt publication is idempotent and requires the same
concrete local-agent authorization boundary as ingress. Provider-native
payloads and diagnostics are not part of this contract.

Tool summaries may include a runtime-authored `presentation` with the
registered description, canonical category, operation, risk, bounded safe
parameters and invocation summary. Terminal summaries may also include
`durationMs`. These fields are already sanitized at the runtime boundary;
clients should render them directly and must not derive labels by splitting or
translating `toolName`. Raw tool input, output, credentials and local paths are
not part of the presentation contract.

The projected runtime schema and fixtures live beside the backend capsule under
`packages/ravi-os-sdk/src/generated` and
`packages/ravi-os-sdk/src/__tests__/fixtures/channel-runtime-events`.

## Native Channel Drivers

An installed provider can run inside the channel runner through the versioned
`NativeChannelDriver` ABI. The driver receives a channel-scoped host for
ingress, runtime readback and interrupt, output sinks, and lifecycle event
sinks. Optional text delivery, chat actions, and presence surfaces join the
same outbound consumers as built-in channels.

Each module must expose the named `nativeChannelDriver` export:

```ts
import type {
  NativeChannelDriver,
} from "@ravi-os/sdk/native-channel-driver";

export const nativeChannelDriver: NativeChannelDriver = {
  descriptor: {
    protocol: "ravi.channel.native-driver",
    schemaVersion: 1,
    driverId: "example.native",
    provider: "example",
    capabilities: ["inbound"],
  },
  createRuntime({ channel }) {
    return {
      descriptor: {
        protocol: "ravi.channel.native-driver",
        schemaVersion: 1,
        driverId: "example.native",
        provider: "example",
        runtimeId: channel.name,
        channelInstanceId: channel.name,
        capabilities: ["inbound"],
      },
      start() {},
      stop() {},
      health: () => ({ status: "connected" }),
    };
  },
};
```

Operators declare local modules explicitly:

```bash
RAVI_NATIVE_CHANNEL_DRIVERS='[
  {
    "protocol": "ravi.channel.native-driver",
    "schemaVersion": 1,
    "provider": "example",
    "moduleSpecifier": "@example/native-channel-driver"
  }
]'
```

Installed package names and absolute `file:///` URLs are accepted. Ravi never
derives a module name from the provider, searches for plugins, or downloads
driver code. ABI version, provider ownership, runtime identity, capabilities,
and optional surfaces are validated before start. Duplicate or incompatible
drivers fail closed.

Drivers start sequentially with enabled channel instances and stop in reverse
order. Health projection includes only lifecycle state, stable reason codes,
timestamps, and reconnect counts; provider payloads, secrets, and thrown error
details are excluded. The ABI introduces no new Ravi capability. Local driver
code runs inside the channel runner, so installation remains an explicit
operator trust decision.

The generated driver schema and neutral fixtures live under
`packages/ravi-os-sdk/src/generated` and
`packages/ravi-os-sdk/src/__tests__/fixtures/native-channel-driver`.

## Wire Contract

Every command call is a POST:

```text
POST /api/v1/<group-segments>/<command>
```

The request body is flat JSON. Positional arguments and options are merged at
the top level:

```json
{
  "name": "main",
  "pattern": "group:120363428558776322",
  "agent": "ravi-web",
  "channel": "whatsapp",
  "session": "ravi-web"
}
```

Generated clients must not send `{ "args": ..., "options": ... }` wrappers.

The HTTP transport sends:

- `Authorization: Bearer <rctx_key>`
- `x-ravi-sdk-version`
- `x-ravi-registry-hash`

## Streaming

Use `@ravi-os/sdk/streaming` for server-sent event streams:

```ts
import { createStreamClient } from "@ravi-os/sdk/streaming";

const stream = createStreamClient({
  baseUrl: "http://127.0.0.1:7777",
  contextKey: process.env.RAVI_CONTEXT_KEY!,
});

for await (const event of stream.events({ subject: "ravi.session.>", noClaude: true })) {
  console.log(event.event, event.data);
}
```

Available streams:

| SDK method | Gateway route | Required scope |
| --- | --- | --- |
| `events()` | `GET /api/v1/_stream/events` | `view:system:events` |
| `tasks()` | `GET /api/v1/_stream/tasks` | `view:system:tasks` |
| `session(name)` | `GET /api/v1/_stream/sessions/<name>` | `access:session:<name>` |
| `audit()` | `GET /api/v1/_stream/audit` | `view:system:audit` |

Streams always require a valid context key, even when ordinary open commands do
not.

## Binary Responses

Commands marked with `@Returns.binary()` return a raw `Response` on successful
2xx calls. Error responses still map to typed SDK errors.

```ts
const response = await client.artifacts.blob("art_123");
const bytes = await response.arrayBuffer();
```

## Error Handling

All transports throw the same error hierarchy:

- `RaviAuthError` for 401 responses
- `RaviPermissionError` for 403 responses
- `RaviValidationError` for 4xx validation failures, with `issues[]`
- `RaviInternalError` for 5xx responses
- `RaviTransportError` for network, timeout, or transport failures

```ts
import { RaviError, RaviValidationError } from "@ravi-os/sdk/errors";

try {
  await client.artifacts.show("missing");
} catch (error) {
  if (error instanceof RaviValidationError) {
    console.error(error.issues);
  } else if (error instanceof RaviError) {
    console.error(error.status, error.command, error.message);
  }
}
```

## Codegen

Regenerate the TypeScript client from the live registry:

```bash
bun run sdk:generate
```

Check committed generated files for drift:

```bash
bun run sdk:check
```

Generate the OpenAPI snapshot:

```bash
bun run docs:openapi
```

Generate the Swift SDK:

```bash
bun src/cli/index.ts sdk swift generate
```

Generated TypeScript files live in `packages/ravi-os-sdk/src`:

- `client.ts`
- `schemas.ts`
- `types.ts`
- `version.ts`

Hand-written SDK files contain transports, error mapping, streaming helpers, and
package integration code.

## Published Exports

The published TypeScript package exports:

```ts
import { RaviClient } from "@ravi-os/sdk/client";
import { createChannelBackendClient } from "@ravi-os/sdk/channel-backend";
import { createChannelRuntimeClient } from "@ravi-os/sdk/channel-runtime-events";
import type { NativeChannelDriver } from "@ravi-os/sdk/native-channel-driver";
import { createHttpTransport } from "@ravi-os/sdk/transport/http";
import { createStreamClient } from "@ravi-os/sdk/streaming";
import { RaviError } from "@ravi-os/sdk/errors";
```

The repo contains an in-process transport at
`packages/ravi-os-sdk/src/transport/in-process.ts`, but it is monorepo-internal
and is not exported by the published package.
