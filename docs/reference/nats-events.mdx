---
title: NATS Event Bus
description: Complete reference for all NATS topics, payloads, and event flow in Ravi.
---

NATS is Ravi's central pub/sub backbone. All messages, prompts, tool calls, and responses flow through it as events on hierarchical topics.

## Concepts

- **Topic/Subject** — Hierarchical namespace separated by `.` (e.g., `ravi.session.main.prompt`)
- **Event** — JSON payload published to a subject
- **Wildcards** — `*` matches one level, `>` matches multiple levels
- **Connection** — Direct TCP to `nats://127.0.0.1:4222` (no HTTP/WebSocket intermediary)

## Session Events

Events scoped to a session name (e.g., `agent-main-abc123`).

| Topic | Payload |
|-------|---------|
| `ravi.session.{name}.prompt` | `{ prompt, source?, context?, _agentId? }` |
| `ravi.session.{name}.response` | `{ response, target?, _emitId, _instanceId, _pid, _v: 2 }` |
| `ravi.session.{name}.claude` | Raw Claude SDK event: `{ type: "system"/"assistant"/"result"/"silent"/... }` |
| `ravi.session.{name}.tool` | Start: `{ event: "start", toolId, toolName, safety, input, timestamp, sessionName, agentId }` |
| `ravi.session.{name}.tool` | End: `{ event: "end", toolId, toolName, output, isError, durationMs, timestamp, sessionName, agentId }` |
| `ravi.session.{name}.stream` | `{ chunk }` — text delta streaming for TUI |
| `ravi.session.abort` | `{ sessionKey?, sessionName? }` — abort ephemeral session |

The prompt topic goes via JetStream WorkQueue stream (`SESSION_PROMPTS`). All others are plain NATS pub/sub.

## Inbound Events (Channels to Bot)

| Topic | Payload |
|-------|---------|
| `ravi.inbound.reaction` | `{ targetMessageId, emoji, senderId }` |
| `ravi.inbound.reply` | `{ targetMessageId, text, senderId }` |
| `ravi.inbound.pollVote` | `{ pollMessageId, votes: [{ name, voters[] }] }` (subscribed by the approval service; no Ravi publisher today) |

Inbound WhatsApp messages arrive on the `CHANNEL_INBOUND` stream, published by the `ravi channels` runner on `ravi.channel.inbound.whatsapp.{message|reaction|connection}.{instanceId}` (envelope `WhatsAppInboundEvent`, `schemaVersion: 1`). Telegram/Discord messages arrive from the optional legacy Omni bridge on `message.received.{channelType}.{instanceId}`. Both are routed into sessions by `ChannelInboundPipeline` (`src/channels/inbound/pipeline.ts`), not published as Ravi pub/sub aliases like `whatsapp.*.inbound`. Omni events with a WhatsApp-family channel type are ignored. Emoji reactions are normalized to the canonical trigger subject `ravi.inbound.reaction`; `whatsapp.*.reaction` is not published.

Reaction events are correlation signals. Use `targetMessageId` to look up routine-owned state; do not assume the event includes the original chat, caption, media metadata, or domain object.

## CLI Tool Events

When agents execute CLI tools, events are emitted:

```
ravi.{sessionKey}.cli.{group}.{command}
```

Example: `ravi.agent:main:main.cli.contacts.add`

Standalone CLI commands that are not tied to a session use `_cli` as the session token:

```
ravi._cli.cli.{group}.{command}
```

## JetStream Streams

| Stream | Consumer | Filter | Source |
|--------|----------|--------|--------|
| `CHANNEL_INBOUND` | `ravi-whatsapp-messages` | `ravi.channel.inbound.whatsapp.message.>` | channel runner (WhatsApp messages) |
| `CHANNEL_INBOUND` | `ravi-whatsapp-reactions` | `ravi.channel.inbound.whatsapp.reaction.>` | channel runner (WhatsApp reactions) |
| `CHANNEL_INBOUND` | `ravi-whatsapp-connection` | `ravi.channel.inbound.whatsapp.connection.>` | channel runner (QR, connected, disconnected) |
| `SESSION_PROMPTS` | `ravi-prompts` | `ravi.session.*.prompt` | ravi (internal routing) |
| `MESSAGE` | `ravi-messages` | `message.received.>` | legacy Omni bridge (Telegram/Discord) |
| `INSTANCE` | `ravi-instances` | `instance.>` | legacy Omni bridge (connection events) |
| `REACTION` | `ravi-reactions` | `reaction.received.>` | legacy Omni bridge (emoji reactions) |

The daemon and the CLI reach the WhatsApp runner over request/reply on `_RAVI.channels.whatsapp.rpc.{instanceId}`. Pairing relays are `ravi.whatsapp.qr|connected.{instanceId}` for WhatsApp and `ravi.bridge.qr|connected.{instanceId}` for the legacy bridge.

## Programmatic API

```typescript
import { nats } from "./nats.js";

// Publish event
await nats.emit("ravi.session.main.prompt", { prompt: "oi" });

// Subscribe (wildcards)
for await (const event of nats.subscribe("ravi.session.*.prompt")) {
  console.log(event.topic, event.data);
}

// Multiple topics
for await (const event of nats.subscribe("ravi.session.*.response", "ravi.session.*.tool")) {
  console.log(event.topic, event.data);
}
```
