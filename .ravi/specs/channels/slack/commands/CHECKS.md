# Checks

- A `slash_commands` envelope MUST be acked and MUST be published as `ravi.inbound.command` without the token and without the `response_url`.
- Help, usage and an unknown word MUST be answered inside the ack when Slack accepts a payload there, and MUST leave the ack empty when it does not.
- A slash command MUST NOT enter the durable Slack inbox, MUST NOT publish a session prompt and MUST NOT be published twice for one envelope id.
- A command from another workspace, from a runner that cannot read its own workspace, or from another app than the one the connection named MUST be dropped.
- A command with no usable `response_url` and no static answer MUST NOT run.
- A `response_url` on `https://hooks.slack.com/commands/` (or `/actions/`, or `/app-actions/` for a message shortcut) or on `https://<workspace>.slack.com/commands/` MUST be accepted, and any other host, path, port or credential MUST be refused. The workspace host MUST NOT be accepted for `/actions/`.
- A command that cannot be handed to Ravi MUST be answered to the person once and MUST NOT be published again.
- A command envelope id MUST be remembered for the retry window, whatever other envelopes arrive, and a command MUST be stamped when it arrives, before any await.
- The sixth post to one response handle MUST be refused before any request is made, two callers that arrive together MUST NOT both take the last use, a post Slack refuses MUST give its use back and a request that fails without an answer MUST NOT.
- A Slack user with no contact MUST get a private refusal and MUST NOT run any operation.
- A contact without access to the chat's session MUST NOT read it; a contact with access but without `modify` MUST NOT close a thread, close idle threads or stop a turn, and nothing MUST run before the refusal (`src/chat-commands/engine.test.ts`, `close idle` included).
- A contact that modifies the session but lacks the CLI's capability for the operation MUST be refused, and the check MUST run as `channel-command` with the contact as subject.
- A `channel-command` check without a contact MUST be denied, and neither an agent's runtime context, the local operator nor a Console invocation the daemon happens to run inside MUST be able to stand in for the contact (`src/cli/command-access.test.ts`).
- The command authority (`src/cli/command-access.ts`) and the permission provider contract (`src/permissions/provider-types.ts`) MUST NOT name any channel; a test reads both files and fails on a channel name.
- The owner contact MUST be able to run every command.
- A configured external authority MUST be able to refuse a command's read of a session the contact's local grants allow.
- `close` MUST show the active triggers that hold a thread open and the way out, and MUST explain the other refusals.
- `status` MUST count every open thread, and `close idle` MUST reach old threads behind more newer ones than a page holds.
- `close idle` MUST skip threads that are working, have an open question, have an answer not delivered or a return pending, and MUST stop at 25 per call.
- `close idle` MUST NOT close a thread that has a turn running, work queued or recent activity in the runtime's records, even when its health sample says idle or its lifecycle date is old.
- `stop` MUST say nothing is running when no turn is, and MUST NOT claim a stop after a timeout.
- A command older than 60 seconds, or stamped in the future, MUST NOT run.
- Every command that reaches the daemon MUST publish `ravi.audit.chat_command` (with `channel: "slack"`) without the text typed, the thread name, the `response_url` or a token. A command the runner refuses before publishing is visible only in the runner's log.
- The grammar, the freshness window, the authority, the operations and the audit MUST live in `src/chat-commands/` and the Slack adapter MUST only supply the event, the contact, the session of the chat, the Slack threads and the answer (spec `permissions/chat-commands`).
- A failure while resolving the person, the session or the authority MUST be answered with a retry message and audited.
- A chat whose route forces a session of another agent MUST NOT run a command.
- A command that goes stale while the access metadata loads MUST NOT run.
- `close idle` MUST NOT let refused threads use up its batch: it MUST count only the closes it made and MUST bound the tries.
- Stopping the consumer MUST wait for the command being answered.
- The card of a thread Ravi opened MUST carry Fechar and Parar (each behind Slack's own confirmation, carrying no thread id) while the thread is not closed, and a card built without `controls`, like a cloud run's, MUST NOT.
- A click on Fechar or Parar MUST run the engine command `close <ts>` or `stop <ts>` for the thread whose card was clicked, found among the threads of the session the clicked chat resolves to, as the contact of the Slack user of the payload; it MUST NOT name another chat's thread, MUST NOT run without a contact, without `modify` on the session or without the CLI's capability, MUST NOT run when it arrived late or with no arrival time or with a `ts` that is not a Slack timestamp, MUST be audited with `surface: "button"`, and MUST be answered once when Slack delivers the same envelope twice.
- The answer to a click on Fechar or Parar MUST be ephemeral and MUST say `replace_original: false`, so the card the button is on is not replaced: a close has already refreshed it to "closed" and the answer MUST NOT overwrite it (`src/channels/slack/thread-controls.test.ts`, "answers a click on its own, without replacing the card the button is on"). Only a shortcut's confirmation card is replaced (`src/channels/slack/thread-shortcuts.test.ts`).
- `stop <thread>` MUST interrupt the turn of the thread's own session and not the chat's, MUST say when the thread is not found or has no session left, and MUST be refused before the thread is looked up when the person cannot modify the session.
- The runner MUST publish `routeAccountId` on every interaction it publishes.
- `close` and `stop` MUST be asked a mutating capability: a declared access that is not `mutate` MUST be refused, and a contact that modifies the session but lacks the CLI's capability for `sessions close-thread` or `sessions runtime interrupt` MUST be refused with the missing capability named (real contact, real command-level check, real CLI metadata).
- `status <thread>` MUST say that thread's own state (closed or not, working or idle, time since its last activity, what waits on someone), found among the threads of the session of the chat, with the rights of a plain `status` and no capability of the CLI; it MUST say when the thread is not found.
- A message shortcut (`message_action` with one of the three callback ids) MUST name the thread by its root (`thread_ts`, or the message's own `ts`), found among the threads of the session the chat resolves to, as the contact of the Slack user of the payload; it MUST NOT read anything the message says, and MUST NOT run with a `ts` that is not a Slack timestamp, or with no arrival time.
- The status shortcut MUST answer as a private card in the thread, and only through the response handle when that card could not be sent. The close and stop shortcuts MUST NOT change anything when picked: they MUST send a private card with Confirm and Cancel, and the card MUST carry only the thread and the time it was asked and MUST NOT name a person.
- A confirmation MUST run the engine command `close <ts>` or `stop <ts>` with the authority read at that moment (`modify` on the session and the CLI's capability), MUST replace the card with the answer, MUST be audited with `surface: "shortcut"`, MUST NOT run when asked more than ten minutes ago or from the future, MUST NOT run when it arrived late, and Cancel MUST run nothing.
- A shortcut whose response handle Ravi does not trust MUST still be published, without the handle and without the URL; any other interaction with such a handle MUST be refused (`src/channels/slack/socket-mode.test.ts`, "response handle of an interaction").
- The runner MUST publish the `callback_id` of a shortcut as `callbackId` and MUST NOT publish the message's text or the `response_url` (`src/channels/slack/socket-mode.test.ts`, "message shortcut").
- A tap Slack delivers twice MUST be answered once, per consumer, from a memory bounded to 1000 envelope ids (`src/channels/slack/envelope-dedupe.test.ts`).
- The access the Slack adapter declares for closing a thread MUST equal, field for field, what the CLI declares for `sessions close-thread`.
- A chat that resolves to a thread's own session (its key carries `:thread:`) MUST still look threads up, and ask the close, under the parent session (`src/channels/slack/thread-controls.test.ts`).
- A shortcut or a button MUST name the thread by the channel it was used in and its root `ts`: a thread of another channel of the same session with the same root MUST NOT answer, and the answer MUST be the clicked chat's thread whichever of the two was updated last. A typed command MUST NOT be scoped to a chat (`src/channels/slack/thread-controls.test.ts`).
- A confirmation click MUST be read only from the chat of its card or from a DM with the app (`D…`), and a cancellation has no chat to hold (`src/channels/slack/thread-shortcuts.test.ts`).
- The log line for a shortcut that goes without its response handle MUST say whether the shape is untrusted or the store failed (`describeSlackResponseUrlFailure`, `src/channels/slack/interactions.test.ts`).
- `bun test src/chat-commands/ src/channels/slack/slash-commands.test.ts src/channels/slack/slash-command-handler.test.ts src/channels/slack/interactions.test.ts src/channels/slack/thread-card.test.ts src/channels/slack/thread-controls.test.ts src/channels/slack/thread-shortcuts.test.ts src/channels/slack/private-card.test.ts src/channels/slack/envelope-dedupe.test.ts src/cli/command-access.test.ts` MUST pass.
- `bun test src/channels/slack/socket-mode.test.ts -t "slash commands"` and `-t "message shortcut"` MUST pass.
- `bun run typecheck` MUST pass.
