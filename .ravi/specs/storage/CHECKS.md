# Storage Checks

## Surface Checks

- The CLI MUST expose exactly one group `storage` with exactly one operation
  `cleanup`; no `status`, `plan` or `policy` operation MUST exist.
- `ravi storage cleanup --help` MUST be generated by the real decorator contract
  and MUST list `--tier routine|weekly`, `--execute`, `--json`.
- `ravi storage cleanup` without `--tier` MUST exit `2` (`USAGE_ERROR`) with
  `acceptedValues: ["routine","weekly"]`.
- `ravi storage cleanup --tier bogus` MUST exit `2` and MUST NOT touch disk.
- `--json` output MUST validate against the declared `@Returns` schema and MUST
  include `tier`, `dryRun`, `policyVersion`, `policyHash`, `bytesBefore`,
  `bytesAfter`, `freedBytes`, `areas`, `errors`, `receiptId`.
- Human output and `--json` numbers MUST be equal for the same fixture.

## Safety Checks (adversarial fixtures)

- **Traversal**: a candidate path containing `..` or escaping its allowlist root
  MUST be rejected and preserved; the resolved real path containment check MUST
  be tested directly.
- **Symlink**: a symlink in a temp allowlist root pointing outside the root MUST
  NOT be followed or deleted; `lstat` MUST be used.
- **Active lock**: with a live lock held, a second invocation MUST fail closed
  (stable code, no mutation) and MUST NOT remove anything.
- **Active worktree**: a dirty, stashed or unpushed Git worktree MUST be preserved
  even when named like a scratch candidate.
- **Non-terminal task**: an `open`/`in_progress`/`blocked` task older than 20 days
  MUST be preserved.
- **Omni hold**: an Omni object carrying a hold MUST be preserved; when the Omni
  reference check is unavailable or indeterminate, all Omni objects MUST be
  preserved and the run MUST record the limitation.
- **Policy drift**: a receipt whose `policyHash` differs from the running policy
  MUST be surfaced and MUST NOT be treated as authoritative.
- **Receipt recursion**: receipt retention MUST NOT delete the in-flight receipt
  and MUST NOT re-scan the receipt directory as a cleanup allowlist root.
- **Dry-run immutability**: after a dry-run over a fixture, a checksum tree of the
  fixture MUST be unchanged, including mtimes of non-candidates.
- **Execute scope**: `--execute` on the fixture MUST remove exactly the eligible
  set shown by dry-run and nothing else.

## Deterministic Checker

A checker that does not live in the candidate package MUST validate, against the
frozen candidate SHA:

- the surface (`--help` shape, single operation, accepted values, exit codes);
- the JSON schema/`@Returns` contract;
- the fixture matrix above (including dry-run immutability and execute scope);
- that no command other than `storage cleanup` was added.

The checker MUST be runnable outside the candidate worktree and MUST be the same
input used for the independent verification task.

## Commands

- `bun test src/cli/commands/storage.test.ts`
- `bun test src/storage/`
- `bun run gen:commands` (barrel MUST be regenerated, not hand-edited)
- `bun run typecheck`
- `bun run build:cli`
- `bun src/cli/index.ts storage cleanup --help`
- `bun src/cli/index.ts storage cleanup --tier routine --json` (no mutation)
- `bun src/cli/index.ts storage cleanup --tier routine --execute --json` (fixture only)

## Global Contract Checks

- Errors MUST use the `cli` envelope with `op = "storage cleanup"`.
- Exit codes MUST follow `0` success / `1` execution / `2` usage / `3` blocked.
- `--json` MUST exist on the command (json-coverage meta-test).
- No `list`/`ls` operation exists, so pagination meta-tests do not apply.
