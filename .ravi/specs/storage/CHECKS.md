# Storage Checks

## Surface Checks

- The CLI MUST expose exactly one group `storage` with exactly four operations:
  `cleanup`, `report`, `summary`, `schedule`. No `status`, `plan` or `policy`
  operation MUST exist.
- `ravi storage cleanup --help` MUST be generated by the real decorator contract
  and MUST list `--tier routine|weekly`, `--notify <session>`, `--execute`, `--json`.
- `ravi storage cleanup` without `--tier` MUST exit `2` (`USAGE_ERROR`) with
  `acceptedValues: ["routine","weekly"]`.
- `ravi storage cleanup --tier bogus` MUST exit `2` and MUST NOT touch disk.
- `ravi storage cleanup --notify <session>` without `--execute` MUST exit `2`.
- `ravi storage schedule` without `--execute` MUST exit `3` with the plan and
  MUST NOT write a cron job; with `--execute` it MUST create the canonical job
  once and then report `unchanged`.
- `ravi storage report` and `ravi storage summary` MUST exit `0`, write nothing
  (no receipt, no lock, no directory) and MUST NOT mutate any candidate root.
- `cleanup --json` MUST validate against the declared `@Returns` schema and MUST
  include `tier`, `dryRun`, `policyVersion`, `policyHash`, `freedBytes`,
  `wouldFreeBytes`, `classes`, `disk.before`/`disk.after`, `errors`, `blocked`,
  `limitations`, `removed`, `preserved`, `receiptId`, `receiptPath`.
- `report --json` MUST include one row per class (`STORAGE_CLASSES`) with
  `scopeBytes`, `eligibleBytes`, `inDoubtBytes`, `preservedBytes`, `candidates`,
  `preserved`, `limitations`, plus `totals` and `disk`.
- `summary --json` MUST include `since`, `runs`, `executedRuns`, `freedBytes`,
  `wouldFreeBytes`, per-class freed bytes, `driftedReceipts`, `invalidReceipts`.
- Human output and `--json` numbers MUST be equal for the same fixture: the
  human `freed`/`would free` value MUST match `freedBytes`/`wouldFreeBytes`.

## Class Checks (v2)

- `backups-superseded`: only the newest entry of each type survives; older entries
  of the same type are candidates; a name without a recognizable timestamp is
  preserved as in doubt.
- `instance-attachments`: only files matching `<epochMs>-<externalId>.<ext>` older
  than 90 days are candidates; other names are preserved as in doubt; nested
  directories are outside the class.
- `claude-jsonl`: `*.jsonl` older than 90 days is a candidate; nothing under a
  `memory` segment is ever a candidate, regardless of age.
- `omni-broadcast-mp4`: a candidate requires a matched `status@broadcast` row, the
  file name equal to `external_id`, and both the file and the message older than
  7 days. No match, mismatch or unavailable source preserves the file in doubt.
- `codex-inactive`: requires `payload.originator === "ravi"` **and** proven
  not-live. `codex_exec` rollouts and unreadable headers are preserved as in doubt.

## Safety Checks (adversarial fixtures)

- **Traversal**: a candidate path containing `..` or escaping its allowlist root
  MUST be rejected and preserved; the resolved real path containment check MUST
  be tested directly.
- **Symlink**: a symlink in a temp allowlist root pointing outside the root MUST
  NOT be followed or deleted; `lstat` MUST be used.
- **Protected roots**: with protected roots in the real host shape (`<home>/.ravi`,
  `<home>/.codex`, ...), every dry-run candidate MUST be removable by `--execute`
  (candidate set == removed set), and a crafted candidate outside its own class
  root inside a protected root MUST still be refused as `protected path`.
- **Staged lock**: a lock file that exists but is still empty MUST NOT be stolen
  while fresh; only a dead holder or a lock older than the stale window may be
  taken over.
- **Active worktree**: a dirty, stashed or unpushed Git worktree MUST be preserved
  even when named like a scratch candidate.
- **Non-terminal task**: an `open`/`in_progress`/`blocked` task older than 20 days
  MUST be preserved.
- **Refreshed mtime**: a candidate whose mtime is renewed after the scan MUST be
  preserved by the execute-time re-check, with a reason — in **every** class,
  `codex-inactive` included.
- **Vanished supersession**: if the newest backup of a type disappears between the
  scan and the execute, the older entry that became the newest MUST be preserved
  instead of leaving the type with no backup.
- **Omni hold**: an Omni object carrying a hold MUST be preserved; when the Omni
  reference check is unavailable or indeterminate, all Omni objects MUST be
  preserved and the run MUST record the limitation.
- **Policy drift**: a receipt whose `policyHash` differs from the running policy
  MUST be listed in `driftedReceipts`, excluded from `freedBytes`, and MUST make
  the summary exit non-zero.
- **Receipt recursion**: receipt retention MUST NOT delete the in-flight receipt
  and MUST NOT re-scan the receipt directory as a cleanup allowlist root.
- **Receipt cap**: after `maxCount + n` runs (dry-run included) the directory MUST
  hold at most `maxCount` receipts.
- **Receipt damage**: invalid dates or non-finite numbers MUST land in
  `invalidReceipts`, never be normalized to zero.
- **Dry-run immutability**: after a dry-run over a fixture, a checksum tree of the
  fixture MUST be unchanged, including mtimes of non-candidates.
- **Dry-run accounting**: a dry-run receipt MUST carry `freedBytes: 0` and the
  estimate in `wouldFreeBytes`; `summary` over dry-run + execute MUST equal the
  bytes the execute removed (never the double).
- **Execute scope**: `--execute` on the fixture MUST remove exactly the eligible
  set shown by dry-run and nothing else.

## Deterministic Checker

A checker that does not live in the candidate package MUST validate, against the
frozen candidate SHA:

- the surface (`--help` shape, four operations, accepted values, exit codes);
- the JSON schema/`@Returns` contract for all four operations;
- the fixture matrix above (including dry-run immutability, execute scope and the
  v2 class matrix);
- that no command outside the four `storage` operations was added.

The checker MUST be runnable outside the candidate worktree and MUST be the same
input used for the independent verification task.

## Global Contract Checks

- Errors MUST use the `cli` envelope with the operation's own `op`.
- Exit codes MUST follow `0` success / `1` execution / `2` usage / `3` blocked.
- `cleanup` and `schedule` MUST declare `requiresConfirmation: true`, and
  `--execute` MUST be the last declared option of `cleanup`.
- `--json` MUST exist on every operation (json-coverage meta-test).
- No `list`/`ls` operation exists, so pagination meta-tests do not apply.
