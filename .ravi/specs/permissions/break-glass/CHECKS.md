# Checks

- `permissions allow --apply` MUST be refused, before any profile, grant, tag or agent ceiling write, for a profile of any name whose capabilities include `admin:system:*` or `execute:executable:*`, for an admin profile by name (`admin`, `owner`, `superadmin`), and for a stored profile that already carries break-glass.
- A narrow profile, including `execute:executable:<pattern>` other than `*`, MUST still apply.
- The preview of a break-glass profile MUST carry no `nextCommand` and MUST say it is break-glass.
- An agent turn holding `admin:system:*` MUST NOT tag a contact `permission-admin|owner|superadmin` (any spelling) or with a profile that carries break-glass, through `contacts tag`, `contacts set tags` or `tags attach`.
- The local operator terminal MUST still tag a contact `permission-owner`, and an admin agent MUST still remove it.
- `tags create` and `tags set` MUST refuse a permission definition that carries break-glass, for every caller; a plain tag with the same metadata MUST NOT be refused.
- An existing grant that carries break-glass MUST NOT be revoked by a refused apply.
- `src/permissions/break-glass.ts` MUST NOT name any channel.
- An agent turn holding `admin:system:*` MUST NOT link an identity to, merge into or out of, or set the email of a contact holding break-glass; the stranger MUST NOT materialize `admin:system:*`. The operator terminal MUST still link, and an admin agent MUST still link an ordinary contact.
- An agent turn MUST NOT activate a dormant break-glass contact by `contacts allow`, `approve`, `add` or `set opt-out false`.
- An agent turn MUST NOT raise another agent to `full-access`, `admin:system:*` or `execute:executable:*` by `agents permissions`, `agents set <id> defaults` or a Library install/update profile, and a refused install MUST leave no agent; the operator terminal MUST still do it, and an agent MUST still narrow another (`execute:executable:git`) or set unrelated defaults.
- From an agent turn, calling the sinks directly (`addContactTag`, `updateContact` tags, `dbEnsureContactChatGrant`, `dbUpdateAgent` defaults) with break-glass MUST be refused; the same write inside `runApprovedBreakGlassGrant`, or from the operator terminal, MUST pass.
- `instances set defaultContactTags` MUST refuse permission tags from any caller, and the inbound intake MUST drop permission tags from instance defaults; approving such a sender MUST NOT materialize any capability.
- `instances pending approve` MUST NOT activate a dormant break-glass contact from an agent turn.
- `bun test src/cli/commands/permissions.test.ts src/permissions/privileged-contact-writes.test.ts src/permissions/break-glass.test.ts src/permissions/break-glass-identity.test.ts` MUST pass.
- `bun run typecheck` MUST pass.
- An admin profile MUST be recognized in every spelling the contact-policy provider reads (`Admin.`, `admin_`, `OWNER`), including on a global (`--force`) grant, and its preview MUST show `admin:system:*` instead of failing as an unknown profile.
- A permission definition MUST be judged after the casing the tag store applies: `--kind SYSTEM --source Permissions` and `tags set <slug> source PERMISSIONS` are permission definitions.
- `tags attach` of a break-glass tag to a non-contact asset (chat, task) MUST NOT be refused by this rule; only a contact binding confers authority.
- A contact merge MUST NOT carry a break-glass tag from the source to the target, and MUST say so on stderr.
- `ensureAgentDefaultsCapability` MUST refuse a break-glass capability from an agent turn.
- `runApprovedBreakGlassGrant` MUST refuse an asynchronous body; malformed capabilities MUST be ignored, not thrown on.
- A terminal write that wakes dormant break-glass on an agent, or activates a contact holding it, MUST warn on stderr.
