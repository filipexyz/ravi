# Owner Authority / WHY

On 26/11/2026 the owner (Luís) talked to a client agent (`convit-omie`) in a
WhatsApp group and the agent could not run `cd` or `codex`: the agent's
ceiling is a closed list of executables, and the owner's turn was issued as
"agent ∩ person", so the agent's list cut him. His request: "I talk to an
agent in a group and it reuses MY authority for any other operation", with a
rule that fits in one sentence.

The previous rule (`permissions/user-overlay`: the overlay never widens the
agent) protects against a person getting more than the agent was meant to
do. For the owner that protection is backwards: the owner can already do all
of it from the terminal, so cutting the owner's turn only forces a detour.

Why the owner's own global power and not a chat grant: a chat grant can be
given in a chat by a chat admin; owner authority must come from the
operator-level tags that `permissions/break-glass` already restricts.
